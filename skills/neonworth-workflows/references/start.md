# Create or resume

1. Establish whether this is a new instance or an interrupted/existing one. Use the user's Site link, retained project ID and operation receipt. If a previous registration outcome is uncertain, inspect the matching Site before creating another. Do not select a similarly named Site by guesswork. Ask only for an unresolved destination or required first-history date.
2. Read the [Sites profile](../../../profiles/sites/README.md) and [finance harness](../../../integrations/gpt-finance/README.md). Preflight the authorized financial source and the ability to write/read back the intended Site's stored state. Discover actual tool schemas; a tools list alone does not establish accessible financial data. Missing investment history must remain unknown, not be synthesized from bank rows. If a required capability fails, preserve any existing instance and report that specific blocker.
3. For a new instance, select a reviewed release, export a separate instance with `npm run sites:export -- /absolute/new-empty-instance`, and follow the profile's setup contract. Establish the user's reporting timezone and configure `FINANCE_CONFIG.timeZone` in that private instance before its first build; do not silently substitute the template's UTC default for a supplied timezone. Use native Sites registration once, record the returned project ID immediately, and verify owner-private access. Track the generated `.openai/hosting.json` identity and `.openai/template.json` upstream provenance only in that private instance's source repository; the latter enables later safe source upgrades. Never copy a previous owner's manifest, storage ID, grants or runtime state into a new Site.
4. Run the profile's checks/build and the installed Sites packaging/publication flow. Verify the terminal deployment outcome and exact destination. Do not weaken authentication to get a preview or health check working. Resume a returned saved version/deployment rather than publishing duplicate versions after an uncertain response.
5. Inspect saved state. If a dataset exists, use [refresh](refresh.md); never seed or replace it as a new installation. If it is absent, use the harness's initial-population path with the user-established history start and actual complete source pages. Preserve its `initialOnly:true` guard; a competing first import must fail rather than replace another writer's data. Keep records in transient/private processing, out of source archives and logs. Populate only the confirmed private destination, then verify the persisted source and independent-record checkpoint through the harness.
6. Leave budgets, goals and withdrawal assumptions unset unless supplied by the user. Show unsupported or incomplete evidence honestly. Add recurring updates only if the user asked for them and supplied the time/timezone; follow the scheduling section of [refresh](refresh.md). Return separate code, data and scheduling outcomes.
